# Security policy

English · [Español](#política-de-seguridad)

## Reporting a vulnerability

Please report vulnerabilities privately through GitHub: open the repository's **Security** tab
and choose **Report a vulnerability**. Do not open a public issue for a security problem.

Include what you found, the steps or file that reproduce it, the Amate version or commit, and your
operating system. Amate is maintained by one person, so replies are best effort; you will get an
acknowledgement as soon as the report is read, and credit in the fix unless you prefer otherwise.

## Supported versions

Amate has no release yet. Until the first public release, only the latest commit of the default
branch receives fixes.

## Scope

Amate opens files that may not be trusted. Crashes, hangs or memory exhaustion caused by a file or
a search pattern, data loss when saving, and anything that makes Amate connect to the network
(it never should) are in scope.

# Política de seguridad

## Reportar una vulnerabilidad

Reporta las vulnerabilidades en privado desde GitHub: abre la pestaña **Security** del repositorio
y elige **Report a vulnerability**. No abras un issue público para un problema de seguridad.

Incluye qué encontraste, los pasos o el archivo que lo reproducen, la versión o el commit de Amate
y tu sistema operativo. Amate lo mantiene una sola persona, así que las respuestas son de mejor
esfuerzo; recibirás un acuse en cuanto se lea el reporte, y crédito en la corrección salvo que
prefieras lo contrario.

## Versiones con soporte

Amate todavía no tiene versiones publicadas. Hasta la primera versión pública, solo el último
commit de la rama principal recibe correcciones.

## Alcance

Amate abre archivos que pueden no ser de confianza. Entran en el alcance los cierres inesperados,
los bloqueos o el agotamiento de memoria causados por un archivo o un patrón de búsqueda, la
pérdida de datos al guardar y cualquier cosa que haga que Amate se conecte a la red (nunca debería).
